# Switchboard reference

The [user guide](../README.md#messaging-between-sessions) introduces teaching, Tell and Ask. This page describes the command and delivery contract.

## Messaging between sessions

Right-click a conversation row, or its Mac transcript, and choose **Teach Session To Talk To Other Sessions**. The option is also available for remote sessions on updated homes, including parked sessions; teaching queues instructions without taking over the pane. Converse queues an instruction prompt that teaches the assistant to interpret user requests such as “tell Reviewer to check the tests.” It discovers current names and IDs by ending its reply with one `converse` fenced JSON block: `{"command":"list-sessions"}`. Converse queues a live JSON directory response to that session. No static directory is taught.

Every switchboard command, including Parking Lot commands, must be the last thing in the assistant’s final reply: one `converse` fenced JSON block, starting at the beginning of a line. A short line of prose before it is fine; nothing but whitespace may follow it, and a reply may contain only one command block. A block followed by text, several command blocks, an unclosed fence or invalid command JSON runs nothing, and Converse adds one notice explaining why. Indented, quoted and other-language code blocks are discussion and stay silent. Codex commands are read from its authoritative final answer. App Support `app-control` operations still require the entire final reply. Untaught sessions keep the whole-reply rule, so their protocol discussion never produces notices.

To deliver, the assistant emits `{"command":"tell","to":"SESSION-UUID","text":"message"}` in the same fence. `tell` queues behind existing work, starts when idle, and respects a paused queue. `tell-urgently` interrupts and delivers next, resuming a paused queue. Drafts and attachments stay intact. Parked sessions receive messages without changing pane placement. Both transcripts show sender, recipient and delivery ID; queued means accepted, not read or answered. No extra acknowledgment turn is generated.

For a request that needs an answer, add `"replyExpected":true`. Reply with `"inReplyTo":"REQUEST-UUID"` and the original sender as `to`. The receiving home matches both the request ID and the authenticated sender; a delivery acknowledgment is not an answer. After a completed turn leaves a request unanswered, Converse allows 30 seconds, then makes at most one corrective injection. If that fails, agents watching either participant receive one attention notice. Human-paused queues and approval/input waits are left alone.

If two sessions have ordinary tells queued to each other and neither has produced output for two minutes, Converse injects one existing message once. Both local sessions and updated group homes participate. Cross-home recovery uses fresh authenticated queue reports containing identities only, with one home elected to act. Recovery is recorded before interruption, survives restart, preserves drafts, and never replays the original tell. Older homes reject tracked requests explicitly; they continue accepting ordinary tells. This mechanism detects mutual waiting, not every kind of dependency cycle.

Mac receipts advance through Queued, Processing, Completed (tell) or Awaiting reply / Answered (ask); failed and cancelled turns are explicit. The receiver's pane header and Delivery details retain recent delivery results. Remote transport acknowledgement remains acceptance-only, not proof of turn completion. On restart, an unfinished in-flight delivery is cancelled rather than automatically replayed.

A selected local supervising agent can request one recovery using the host's delivery ID and eligibility evidence. The automatic supervisor also handles one-sided queued deliveries after two minutes without output. Both use the same persisted allowance; completed one-way tells never get reminders. After a failed recovery, one visible escalation replaces further retries. Queue pauses and approval waits remain under human control.

Traffic appears as a single line with its status, arrow, peer and a short excerpt. Desktop hover shows the complete message; on iPad tap a transcript traffic line to open it. Copy/export retains the original text. Desktop message-number hover shows a recorded local date and time when that message has a saved timestamp; legacy messages without one are left undated.

A recognizable whole-reply command from an untaught session gets a visible notice explaining how to enable messaging; nothing is sent. Bare command JSON also gets a formatting notice and never executes. Only successful, completed assistant turns from enabled sessions execute commands. Partial streams, tool output, examples followed by prose or indented, and failed/interrupted replies do not. IDs are recorded with pending delivery before provider execution; restored queues remain paused. Self-messages, missing recipients and messages over 32 KB are rejected visibly. Automatic chains stop after 100 hops, including directory responses. Normal human input starts a fresh chain. The context menu also offers **Disable session messaging**. Teaching and disabling affect the sender; recipients can receive ordinary labeled input without being taught to send.

### Messaging across homes

`list-sessions` includes local sessions and remote sessions from the current group, labeled with their execution home and online/messaging state. Copy the directory’s exact ID: local UUIDs remain supported; remote IDs are `homeDeviceID/sessionUUID`. Both homes need this update for cross-device messaging. Older/unsupported homes are listed with messaging unavailable.

Tells do not acquire a display lease. The recipient must have session messaging enabled on its home; ordinary tells preserve paused queues and drafts. Acceptance means **persisted in the recipient queue**, not read or answered. Duplicate delivery IDs do not enqueue twice. Offline/out-of-group targets fail visibly; an unconfirmed send is not automatically replayed. See [the wire contract](../docs/participant-control.md) and [agent design](../docs/agents.md).
